# Make Knowledge Cards

把一段文章或本地 Markdown/TXT 文件，提炼成一组便于学习与复习的知识卡片。

## 适用输入

| 输入类型 | 处理方式 |
| --- | --- |
| 用户在对话中直接粘贴的正文 | 直接作为输入 |
| 用户提供路径的本地 `.md` / `.txt` 文件 | 先读取文件内容，再提炼 |
| 其他（网页链接、PDF、Word、Anki、图片等） | **不支持**，明确告知用户并提供替代建议（如请用户粘贴文本） |

## 卡片结构

每张卡片必须且只能包含以下四个字段，顺序固定：

1. **标题**：一句话点明本张卡片的知识点，简短、可检索，不加编号以外的修饰。
2. **核心知识**：用 1~3 句凝练陈述该知识点最关键的事实或结论，是整张卡片的骨架。
3. **简明解释**：用 2~4 句把“核心知识”讲清楚，说清为什么、怎么理解，补足必要的背景。**解释只能组织原文已有的信息，不得引入原文没有的新事实、数据或结论。**
4. **例子或自测问题**：二选一，**同样不得引入原文未支持的新事实**。
   - **例子**：给一个贴合原文、能帮助理解的具体实例，应基于原文内容改述或举例。
   - **自测问题**：出一个考察该知识点的小问题（选择/填空/简答），并附简短答案，答案必须能从原文推出。

> 若某个知识点原文确实既无例子空间又无合适自测点，可在该字段写“无”，但尽量优先给出例子。

## 生成工作流

按以下顺序执行，每个步骤都是对最终结果的硬约束。

### Step 1: 读取并理解输入

- 完整读取粘贴文本或文件全文，不要只依赖标题或片段。
- 识别文章的主题、体裁（科普、教程、说明文、论述、小说节选等）和主要信息层次。

### Step 2: 提取候选知识点

- 列出原文中真正重要、可独立成点的知识。判断标准：去掉它，文章的核心信息是否受损。
- 只从原文提取，**严禁编造原文没有的事实、数据、观点**。若原文含糊，保留含糊，不加自己的推断当事实。

### Step 3: 去重与合并

- 删除表达重复、只是换说法重述的知识点，只保留信息量最大的一处。
- 含义接近但角度不同的可合并为一张；合并后若不再是“一个知识点”，则拆开。

### Step 4: 逐点成卡

- 每个知识点生成一张卡片，**一张卡片只讲一个知识点**，禁止把多个知识点塞进一张。
- 逐卡填写四个字段，内容严格来自原文；解释部分可组织语言，但不能新增事实。

### Step 5: 确定卡片数量

- 目标 **5~8 张**。
- 若提炼出的独立知识点不足 5 个，**按实际数量输出**（如 3 张、4 张），不要为了凑数而拆分知识点或注水。
- 若知识点多于 8 个，保留信息量最高、最核心的 8 个，删除次要的；并把取舍标注在输出末尾的“说明”里。
- 原文信息量极少（如不足一个清晰知识点）时，可只输出 1 张或明确告知“信息不足，无法形成多张卡片”。

## 质量规则（输出前逐条自查）

- [ ] 只含重要知识，不含琐碎、无关或重复内容。
- [ ] 每张卡片只有一个知识点。
- [ ] 所有事实、数据、观点都来自原文，无编造；解释与例子也未引入原文未支持的新事实。
- [ ] 卡片之间有覆盖去重，无重复表述。
- [ ] 数量在 5~8 之间，或按要求说明未达标原因。
- [ ] 每个字段都填写完整、无空字段。

## 输出格式

用 Markdown 输出，格式如下（可复制到笔记软件）：

```markdown
# 知识卡片：<文章主题>

## 卡片 1｜<标题>
- **核心知识**：<1~3 句>
- **简明解释**：<2~4 句>
- **例子/自测**：<具体例子，或自测问题 + 简短答案>

## 卡片 2｜<标题>
...
```

在最后用一段 `> 说明：` 注明取舍情况（如有），例如合并了哪些、删除了哪些、数量为何不足或超限。

## 边界与明确不支持

- ❌ 网页抓取：不访问链接、不爬取网页，需要用户粘贴文本。
- ❌ PDF / Word / 其他格式：只处理纯文本与本地 `.md` / `.txt`。
- ❌ Anki 导出：不生成 `.apkg`，只输出 Markdown 卡片，用户可自行导入。
- ❌ 图形界面 / 图片生成：不制作图片版卡片。
