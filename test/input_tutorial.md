# 写一条好的 Git 提交信息

写提交信息是 Git 使用中每天都要做的小事，但写得好不好，差别很大。好的提交信息能让你和队友几个月后还能快速理解这次改动做了什么、为什么做。

最常用的格式是“主题行 + 正文”。主题行（subject）是一句话，用祈使语气简洁说明这次提交做了什么，例如“fix: 修复登录页在移动端错位的问题”。主题行一般不超过 50 个字符。正文（body）写在主题行下方空一行，用来解释“为什么这么做”，而不是重复代码本身。正文里可以说明修改的背景、决策和替代方案。

提交信息里的“类型”也很重要。常见的类型前缀有：feat（新功能）、fix（修复缺陷）、docs（文档改动）、refactor（重构，不改变功能）、test（测试相关）、chore（构建或杂务）。使用统一的前缀，能让提交历史一眼看出每个提交的性质。

另外，一次提交只做一件事。不要在一次提交里既改 bug 又加新功能，这样出了问题不好定位，回滚也困难。一个原子提交应该只包含一个逻辑改动，并且这个改动能够独立通过测试。

写好提交信息的关键，是站在“读的人”的角度去写：未来的你或队友打开 git log 时，能否只看信息就知道改动的内容和原因。能，就是好提交。
